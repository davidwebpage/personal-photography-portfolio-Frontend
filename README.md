# 摄影作品集网站

个人摄影作品集静态网站，用 [Astro](https://astro.build) 构建。无数据库、无后端，构建产物是纯静态文件，可部署到任何静态托管（对象存储 + CDN、GitHub Pages 等）。

## 环境准备（只需做一次）

本项目需要 Node.js（v20+，推荐 v24 LTS）。本机安装在 `~/.local/node`，并已把以下一行加入 `~/.zshrc`：

```bash
export PATH="$HOME/.local/node/bin:$PATH"
```

新开终端后 `node --version` 能显示版本号即就绪。

## 常用命令

在项目目录（`~/personal-photography-portfolio`）下运行：

| 命令 | 作用 |
|---|---|
| `npm install` | 安装依赖（只需跑一次，或依赖变动后） |
| `npm run dev` | 本地预览，浏览器打开 http://localhost:4321 （改文件即时刷新） |
| `npm run dev -- --host` | 同上，但**局域网可访问**——手机连同一个 Wi-Fi 也能打开（见下文「手机 / 平板预览」） |
| `npm run build` | 构建静态站点到 `dist/`（**默认全前端**：图片打进 `dist/`） |
| `npm run build:r2` | 同上，但图片走 Cloudflare R2（需设 `ASSET_BASE_URL`，见「图片托管的两种模式」） |
| `npm run build:local` | 同上，显式指定全前端模式（和 `npm run build` 等价） |
| `npm run deploy` | 构建 + 部署到 Cloudflare Pages |
| `npm run preview` | 本地预览构建产物 |
| `npm run photos` | 处理真实照片（见下文"替换成真实照片"） |
| `npm run colors` | 给照片打色调标签（见「按色调筛选」；加 `--dry` 只预览不写） |
| `npm test` | 跑色调分档的单元测试 |
| `npm run changelog -- "更新内容" "实现方式"` | 往更新日志追加一条记录（见下文「更新日志」） |

## 手机 / 平板预览（局域网）

`npm run dev` 默认只绑本机（监听 `127.0.0.1:4321`），**手机连不上**。要让手机也能看，启动时加一个 `--host`：

```bash
cd ~/personal-photography-portfolio
npm run dev -- --host
```

启动后终端会多打印一行 `Network:`，形如：

```
┃ Local    http://localhost:4321/
┃ Network  http://192.168.1.23:4321/
```

手机连**同一个 Wi-Fi**，浏览器打开那个 Network 地址即可（端口仍是 4321）。这是纯局域网访问，走不了公网，**不消耗手机流量**。

几点注意：

- 服务挂在你那个终端窗口上，**窗口一关服务就停**；要停就按 `Control + C`。
- 内网 IP 会变（换网、重启路由器后），在 Mac 上查当前地址：`ipconfig getifaddr en0`
- 首次启动可能弹 macOS 防火墙提示，选「允许」。

**端口被占用**（报 `EADDRINUSE`）——一般是上次的进程还活着：

```bash
lsof -nP -iTCP:4321 -sTCP:LISTEN   # 看是谁占着，记下 PID
kill <PID>                          # 停掉它，再重新启动
```

**想让 `npm run dev` 默认就能被手机访问**（省掉每次敲 `--host`），在 `astro.config.mjs` 里加一行：

```js
export default defineConfig({
  server: { host: true },
  // …其余配置保持不变
});
```

## 更新日志

项目维护一份 `CHANGELOG.md`，记录每次对网站的改动（更新了什么、怎么实现的），新条目在最上面。

**这是强制的**：项目装了 git 钩子（pre-commit），任何 agent 或人提交代码时，只要本次改动涉及网站内容（`src/`、`scripts/`、`public/`、`package.json`）却没同时更新 `CHANGELOG.md`，提交就会被拦截，必须补记日志后才能提交。所以不管用哪个工具更新，日志都一定会被记录。

记录方式（用脚本，别手写）：

```bash
node scripts/changelog.mjs "更新内容一句话" "实现方式说明"
# 等价于 npm run changelog -- "更新内容" "实现方式"
```

- 忘了这次改了什么？先跑 `node scripts/changelog.mjs --draft`，它会列出当前 git 改动帮你回忆。
- 脚本自动带当天日期，格式统一为 `## YYYY-MM-DD`，下面分「更新内容」「实现方式」两段。
- 记完再提交 git，这样 CHANGELOG 和代码改动一起进版本历史，钩子也会放行。

钩子相关：

- 钩子脚本在 `scripts/git-hooks/pre-commit`，安装脚本 `scripts/install-hooks.sh`（已装好）。
- 如果确实不需要记录（例如只改文档/配置），可跳过：`SKIP_CHANGELOG=1 git commit ...` 或 `git commit --no-verify`。

## 新增 / 替换照片（精简流程）

照片原图有 3G 左右，项目里**平时不保存母版**，需要更新时再临时放进来。脚本已经改成「只增改、不动旧照片」：只处理你放进 `_masters/` 的那几张，原有 164 张记录原封不动。

**需要准备什么**

- 原始照片文件（jpg / jpeg / png / tiff / webp 都行，从百度盘或移动硬盘取回）
- 知道它属于哪个类别或系列

**操作步骤**

1. 在项目里新建 `_masters/<系列slug>/`，把这次要新增或替换的照片放进去。例如：
   ```
   _masters/nature/DSC001.jpg
   _masters/city/我的新照片.jpg
   ```
   系列 slug 要和 `src/data/series.json` 里的 `slug` 一致；不属于任何系列的单图，目录名随便起（例如 `_masters/single/`），页面会自动归到「单幅作品」。
2. 运行 `npm run photos`。脚本会：
   - 只处理 `_masters/` 里这次放的照片，生成 800 / 1600 / 2560 三档 webp 到 `public/photos/<系列>/`；
   - 把新记录**追加**到 `src/data/photos.json`，同名照片则更新那一条；
   - **原有照片记录全部保留**，不会因为这次没放母版而消失。
3. 运行 `npm run colors` 给新照片打色调标签。这一步别省：没打标的照片在任何色调筛选下都会被筛掉。
4. 打开 `src/data/photos.json`，给新照片补 `title`（标题）和 `location`（拍摄地）。已有的手填字段在以后更新时会被保留。
5. 如果是新系列，同步编辑 `src/data/series.json`（标题、简介、封面、年份）。
6. `npm run dev` 预览，满意后 `npm run build`。
7. 确认没问题后，**可以删掉 `_masters/`** 省空间；网站用的是 `public/photos/` 里的派生图，不受影响。下次再加照片，重复以上步骤即可。

> 想换某张已有照片：把新原图用**原来的文件名**放进 `_masters/<原系列>/`，跑一次 `npm run photos` 就会替换那一张，其余照片不受影响。
>
> 想一次批量更新很多张：按上面的做法把要更新的都放进 `_masters/` 再跑一次即可。不需要、也不建议把 164 张母版全部搬回来。

## 手动更新图片（不跑脚本）

> 适合：只加/换一两张图、不想重新处理全部照片时。**前提是图片已经处理成网页用的尺寸**（见下方说明）。

**先说清楚机制**：网页不是直接扫描 `public/photos/` 目录来显示图片的，它读的是 `src/data/photos.json` 这份清单。页面遍历清单里的每一条记录，按记录里的 `src` 路径去加载图片。所以要让一张照片显示，**两样东西必须同时到位**：

1. 图片文件在 `public/photos/<类别>/` 下；
2. `src/data/photos.json` 里有一条记录指向它。

只放图片、不加记录，图片不会出现在网页上；只加记录、文件不存在，会显示破图。平时跑 `npm run photos` 就是一次性把这两件事都做了，手动更新则是自己补。

**手动加一张照片的步骤：**

1. 把图片文件放进对应类别的目录，例如 `public/photos/city/`。文件名建议用照片名，如 `我的照片-1600.webp`。
2. 打开 `src/data/photos.json`，在数组里加一条记录（照现有记录的格式抄）：

```json
{
  "id": "我的照片",
  "series": "city",
  "title": "我的照片",
  "src": "/photos/city/我的照片-1600.webp",
  "srcset": "/photos/city/我的照片-800.webp 800w, /photos/city/我的照片-1600.webp 1600w, /photos/city/我的照片-2560.webp 2560w",
  "width": 1600,
  "height": 1067,
  "year": null,
  "location": "",
  "exif": null
}
```

各字段含义：

| 字段 | 说明 |
|---|---|
| `id` | 照片唯一标识，同一类别内不要重名 |
| `series` | 所属类别 slug，必须是 `src/data/single-categories.json` 里的 slug（`nature`/`city`/`people`/`event`/`space`） |
| `title` | 标题，留空 `""` 就不显示 |
| `src` | 主图路径（网页实际加载这张） |
| `srcset` | 多尺寸清单，`800w`/`1600w`/`2560w` 三档，供浏览器按屏幕选清晰度 |
| `width` / `height` | 主图的宽高（像素），用于布局占位 |
| `year` / `location` | 年份、拍摄地，可留空 |
| `exif` | 拍摄参数（相机/焦段/光圈/快门/ISO/日期），灯箱里显示；没有就写 `null` |

3. 保存后 `npm run dev` 看效果，满意后 `npm run build`。

**关于图片尺寸**：网页用的是压缩后的 webp（最大 2560px 宽）。手动放图时，最好用 `npm run photos` 生成好的成品图，或自己用工具导出成 webp、最长边 2560px 以内。直接丢一张几 MB 的原图进去也能显示，但会拖慢加载，不推荐。

**换图**：把新文件覆盖到同名路径即可（`src` 不变就不用改 JSON）；**删图**：删掉文件，同时删掉 `photos.json` 里对应那条记录。

## 背景音乐

每次**整页打开**网站时，从歌单里随机抽一首循环播放（站内翻页不换歌，音乐连着播）。右上角那个 ♪ 按钮可以随时关掉／打开，鼠标停在按钮上会显示正在放的曲名。

**关于「一进来就播」**：浏览器有一条硬规矩——访客还没跟页面产生过任何互动之前，网页**不许自动出声**（Chrome、Safari、Firefox 全都一样）。这不是代码写得好不好的问题，是浏览器专门设计来拦这件事的，绕不过去。所以现在做的是：

- 页面一加载就立刻尝试播放，不等图片加载完；
- 只要访客做了**任何一个**动作（点击、按键、触摸、滚动）就立刻补启动，不需要特意点哪里；
- 万一被拦住了，音符按钮旁边会出现一行「点一下页面，音乐即响起」，一出声就收走；
- 之前来过的访客（浏览器记住了你在这个站上的互动）往往一打开就直接响。

想让访客**必然**是「点一下就进站、进去就有音乐」，只有一个办法：加一层「点击进入」的封面。这是有背景音乐的摄影站常见做法，代价是访客得先点那一下才看得到内容。要做的话说一声。

加歌两步：

1. 把音乐文件丢进 `public/audio/`；
2. 在 `src/data/music.json` 里加一行：

```json
[
  { "file": "/audio/飞雪玉花-净友钢琴版.mp3", "title": "飞雪玉花 · 净友钢琴版" }
]
```

`title` 只用来做按钮上的提示，随便写。

**格式**：mp3 和 m4a（AAC）都可以，现在的两首就是这两种，浏览器都认。要换新歌的话，导出成 **mp3、128 kbps** 左右最稳——这是兼容性最好的组合，手机上、老浏览器上都能放，一首 2 分钟的曲子大约 1.8 MB。文件控制在 3 MB 以内，太大了会拖慢首屏。你自己扒下来的无损（flac / wav）别直接放，先用播放器或在线工具转成 mp3 128k。

## 单幅作品

顶栏「单幅作品」这一栏放**不属于任何系列**的照片——单张的、临时的、还没凑成组的都放这里。

放法：把照片临时放进 `_masters/single/`（或任何不在系列清单里的目录），运行 `npm run photos` 即可；处理完 `_masters/` 可以删掉。判定规则很简单：**照片的系列名 = 它所在的目录名，凡是目录名不在 `src/data/series.json` 的 slug 清单里，就算单图**。所以：

- 目录名不叫 `single` 也行（比如 `_masters/杂片/`），效果一样；
- 反过来，如果你新开了一个目录想当系列、却忘了往 `series.json` 里登记，那些照片会落到「单图作品」里，而不会凭空消失——发现它们出现在这儿，就说明该去补 `series.json` 了。

**类别内部的顺序**：按拍摄时间（EXIF 里的拍摄日期）**从新到旧**排，最近拍的排最前面，不用手工调。日期来自照片本身的 EXIF，所以「拍的就该在前面的」会自动成立；没有拍摄日期的照片排在最后。获奖页上一条记录挂多张图时，也按同样的规则排。

**按年份筛选**：页面标题底下有一排年份按钮（2026 / 2025 / …），点哪一年就只留下那一年拍的照片，**再点一次同一颗按钮就是取消**，恢复全部。没有单独的「全部」按钮——一颗都没选中时就是显示全部。年份不用手工维护，是从每张照片 EXIF 的拍摄日期里自动列出来的；这一年一张都没有的类别会整块收起来。没有拍摄日期的照片不属于任何年份，只在没选中年份时出现。只剩一个年份时这排按钮不显示。离开这一页再回来会回到「全部」。

**按色调筛选**：年份按钮下面还有一排圆点（红橙黄绿青蓝紫七个色相）。点一个圆点就只留下以该色调为主的照片，同样**再点一次取消**。它和年份是**「并且」**的关系：先点 2024 再点蓝色，留下的是「2024 年拍的、且以蓝色为主」的照片。两个条件叠起来可能一张都不剩，这时会出来一句提示，取消掉一个就恢复。

- **七个档位**：红橙黄绿青蓝紫。**没有「中性」档**——无彩色（灰、黑、白、过暗、过亮）的像素在算色调时直接跳过、不算数，档位只由有颜色的像素决定。所以一张 60% 灰 + 40% 蓝的照片，蓝就是 100% 的主色。整张都没有彩色像素的照片（雪景、雾、黑白）打不出任何档，就不参与色调筛选。
- **一张照片最多挂两个色调**：用得最多的那个必挂；第二名如果和第一名差得不多（**10 个百分点以内**）就也挂上。比如一张照片 40% 是橙色、35% 是蓝色，这两个都有意义，就都挂。
- **圆点灰掉（不可点）**，说明图库里暂时还没有这个色调的照片。圆点排成一条，所以宁可灰着也不抽掉——抽掉中间一个，这条带子就断了。目前紫是灰的，等照片多了自然会亮。

⚠️ **色调是脚本猜的，会猜错。** 这跟年份有本质区别：年份是 EXIF 里的事实，色调是看图拿主意，头名和第二名咬得紧的照片，阈值动一点就翻面。所以把它当「脚本先猜、你事后微调」来用：

- 跑 `npm run colors -- --dry` 可以先看一张表（照片 / 头名 / 次名 / 差值）而不写文件。**调阈值主要就靠它**。满意了去掉 `--dry` 再跑一次写回。
- 觉得哪张分错了，直接改 `src/data/photos.json` 里那条的 `colors` 字段（中文名，如 `["橙", "蓝"]`，最多两个）。**重跑 `npm run colors` 默认只补还没打过标的，手改过的原样保留**，不会被冲掉；确实想全部推翻重算，加 `--force`。
- 分档规则和四个阈值集中在 `scripts/lib/colors.mjs` **文件顶部**，改完跑 `npm run colors -- --force` 生效。改之前建议先 `npm test`——那里面钉着几条边界（比如「刚好差 10 个百分点就挂两个、差 11 就只挂一个」），能挡住手滑改错。

「全部照片」页末尾也会自动多出一组「单图作品」；一张单图都没有时，两处都不显示空分组。

## 拍摄档案的分档

`src/lib/exif-stats.ts` 里几张表的边界都能自己改（改了记得 `npm run dev` 看一眼）：

- **光圈占比**：按具体光圈值逐档列，只露用得最多的 5 档，其余折进「其余 N 档」；
- **快门天梯**：从慢到快一档挨着一档，**空档位也保留**，所以看得出自己常在哪一段、哪一段从来没用过；
- **ISO区间**、**焦段分布**：改 `ISO_BANDS` / `FOCAL_BANDS` 两个数组即可，区间首尾相接就不会漏照片（万一留了缝，脚本会自动把照片归到最近的一档）。

## 维护获奖作品

「获奖作品」栏目的内容全部写在 `src/data/awards.json` 里，**按时间（`date`）从新到旧自动排序**：

```json
[
  {
    "date": "2026-05",
    "competition": "某某国际摄影大赛",
    "award": "风光组 金奖",
    "organizer": "四川省摄影家协会",
    "link": "https://…",
    "photoId": "峰林布依"
  }
]
```

| 字段 | 说明 |
|---|---|
| `date` | 获奖时间，**年月**格式 `YYYY-MM`（用截稿日期）。排序就看它，同月的两条保持文件里的先后顺序 |
| `competition` | 赛事 / 展览全称，作为标题显示 |
| `award` | 奖项，如「优秀奖」「入展」「入围终评」；**跟在赛事名后面同一行显示**（小一号、颜色压暗），留空就不显示 |
| `entries` | **可选**：同一赛事分多季 / 多届时合并成一条，见下方说明。填了它就不用填 `award` |
| `awards` | **可选**：**跨年份**的同一张作品归成一个「作品组」，见「合并写法三」。填了它不用填 `date` / `competition` |
| `organizer` | 主办单位；留空不显示「主办：」这一行 |
| `link` | 外部链接；留空不显示「查看」按钮 |
| `photoId` | 配图：填 `photos.json` 里某张照片的 `id`，就会在奖项下显示这张照片、可点击放大；留空只显示文字。写成数组就能挂多张（如 `["砚湖御镜", "筑梦献国"]`），一个展览入选两件作品时用 |

**合并写法一：同一赛事的多个赛季 / 届次**（一张作品拿了同一大赛的好几季奖，避免重复列一大串）。写 `competition` 当标题，`entries` 每项渲染成一行「名称 · 奖项」，共用同一个 `date` 和 `organizer`：

```json
{
  "date": "2025-09",
  "competition": "“好拍成都”城市摄影大赛",
  "organizer": "成都发布",
  "entries": [
    { "name": "第十二季·绿动成都", "award": "优秀奖" },
    { "name": "第七季·跃动成都", "award": "优秀奖" }
  ]
}
```

**合并写法二：同一张作品拿了不同赛事的奖**（两个赛事、两个主办，但就是同一张片子）。**不写 `competition`**，每个 `entries` 项自带 `name` / `award` / `organizer`，各自渲染成一个完整区块，共用左边「年月」那一栏和一张配图：

```json
{
  "date": "2025-07",
  "entries": [
    { "name": "四川省2025年“新人新作”摄影展", "award": "入展", "organizer": "四川省摄影家协会" },
    { "name": "“好拍成都”城市摄影大赛第十季·热力成都", "award": "优秀奖", "organizer": "成都发布" }
  ],
  "photoId": "那张片子的 id"
}
```

**合并写法三：同一张作品拿的奖跨了年份**（比如 2025 年一个、2026 年一个）。这时不能共用日期，改用 `awards` 把几个奖归成一个「作品组」：一条记录 = 一张作品，组里每个奖一行、**各自带自己的 `date`**，配图挂在整个组上（只出现一次）：

```json
{
  "photoId": "那张片子的 id",
  "awards": [
    {
      "date": "2026-07",
      "competition": "四川省第20届摄影艺术展",
      "award": "入围终评",
      "organizer": "四川省摄影家协会"
    },
    {
      "date": "2025-09",
      "competition": "“好拍成都”城市摄影大赛",
      "organizer": "成都发布",
      "entries": [
        { "name": "第十二季·绿动成都", "award": "优秀奖" },
        { "name": "第七季·跃动成都", "award": "优秀奖" }
      ]
    }
  ]
}
```

排版规则：**页面左边那一栏取组里最新那个奖的年月**（也就是排序用的时间），组里最新的那一行不再重复写年月，只有年月和它不同的奖项前面才标一个日期。上面这个例子左边显示 `2026.07`，2026 那条不再标日期，2025 那条前面标 `2025.09`。

`awards` 里面每一项的写法和普通条目完全一样，`entries` 也能照用。

> 目前 `awards.json` 里**六条记录全部用的是写法三**（作品组），因为每条都涉及「同一张作品拿了几个奖」。写法一、写法二也还能用，只是暂时没数据用到——以后遇到「同一赛事分几季、且都在同一个月」时才需要。

三种写法都保持按时间从新到旧排序（作品组按组里最新那个奖排；组里的奖项行也自动按时间倒序，不用你操心顺序）。文件是空的（`[]`）时，页面显示「获奖与入展记录整理中」。

**配图**：`photoId` 填的是 `photos.json` 里某张照片的 `id`，那张照片得先用 `npm run photos` 处理过（母版放在 `_masters/<类别>/`）。配图不只是「挂在获奖页上」，那张照片同时也会出现在「单幅作品」对应的类别里——**同一份文件，两处引用**。所以给获奖作品选类别时，想清楚它归到哪一类更合适（比如「观众」放在「舞台之上」而不是「人间烟火」）。目前 6 条记录都配好图了。

## 首页背景图

每次打开首页（包括站内点「首页」回到首页）都会从作品里**随机抽一张横构图照片**当背景，所以不需要手动挑。抽取范围在 `src/pages/index.astro` 顶部：默认是 `photos.json` 里所有横构图（宽 ≥ 高）的照片；想只从某个系列里抽，把那里的 `.filter(...)` 改成按 `p.series === '城市切片对应的 slug'` 过滤即可。

## 明暗主题

右上角圆形按钮切换深色 / 浅色，默认跟随设备的深色模式设置。用户点过之后选择存在浏览器本地（`localStorage` 的 `theme`），下次打开沿用。颜色都定义在 `src/styles/global.css` 顶部的 `:root` 里，用 `light-dark(亮色, 暗色)` 写一对值即可。

灯箱看图和系列页封面上的顶栏固定用深色界面（照片才是主体），不跟着切换。

## 图片托管的两种模式

照片和音频可以从两个地方加载，用环境变量 `ASSET_MODE` 切换，**页面代码完全不用改**（开关集中在 `src/lib/asset-url.ts`，所有页面都走它）。

| | 全前端（`local`，默认） | 走 R2（`r2`） |
|---|---|---|
| 图片地址 | `/photos/...`，和网页同一个域名 | `https://pub-xxxx.r2.dev/photos/...` |
| 图片在哪 | 打进 `dist/`，随站点一起部署 | Cloudflare R2 对象存储 |
| 部署包大小 | 约 227MB | 小（图片不进 `dist/`） |
| 换一张图 | 要重新构建 + 重新部署整站 | 只更新 R2 上那 3 个文件，秒级生效 |
| 换台电脑 | `git clone` 完就能构建 | 图片得另外同步（不在 git 里就没有） |

**怎么切**（两条命令）：

```bash
npm run build          # 全前端版（默认）
npm run build:r2       # 走 R2，需要同时设 ASSET_BASE_URL
```

`ASSET_MODE=r2` 却没设 `ASSET_BASE_URL` 时，构建会**直接报错退出**——这是故意的，免得打出个图片全指向空地址的站。构建日志里会打印一行 `[assets] 模式 = ...`，部署错了版本一眼就能看出来。

**线上两版同时在线**：两个 Cloudflare Pages 站点连同一个仓库，靠环境变量区分——

- 全前端站：设 `ASSET_MODE=local`，**不要**设 `ASSET_BASE_URL`
- 走 R2 站：设 `ASSET_MODE=r2` + `ASSET_BASE_URL=https://pub-xxxx.r2.dev`

两个站的构建命令都是 `npm run build` 即可（默认值是全前端，所以走 R2 那个站**必须显式设 `ASSET_MODE=r2`**，否则会跟着变成全前端版）。

本地开发（`npm run dev`）永远是全前端模式，从本地 `public/` 读图，和线上无关。

## 上线部署清单（到时候再办）

1. **域名**：在国内注册商（阿里云 / 腾讯云）购买，例如 `你的名字.com`。

## FAQ

**需要自己写代码吗？**
日常更新只需要：把新照片临时放进 `_masters/<类别>/` → `npm run photos` → `npm run colors` → 补一下标题/地点 → `npm run build`。处理完 `_masters/` 可删。页面结构改动才需要碰代码。

**照片原图会被公开吗？**
不会。`_masters/` 不会进 git，平时甚至不在项目里（只在更新照片时临时放进来），网站只引用 `public/photos/` 里压缩后的副本（最大 2560px 宽，已进 git）。

**访客数据、评论、后台管理？**
都没有——纯静态站。需要留言功能可后期接第三方表单服务（如 Formspree）。

**手机上打不开怎么办？**
`npm run dev` 只绑本机，手机连不上；改用 `npm run dev -- --host`，手机连同一个 Wi-Fi 打开终端里那行 `Network:` 地址即可。详见上文「手机 / 平板预览（局域网）」。
